# Cycle.exe 2.0 — Final Full-Stack Cycling Community Web Application

Cycle.exe 2.0 is a complete, production-grade, full-stack cycling community web application built with **React**, **TypeScript**, **Express**, **Firebase Authentication**, **Cloud Firestore**, and **Firebase Cloud Storage**.

## 2. Core Systems & Workflows

### A. Authentication & Profiles
- **Google One-Click Sign-In** & **Email/Password Registration**.
- Public users can view the community feed, read comments, view rider cards, and inspect published missions.
- Profile editor allows riders to set custom display names, upload profile photos, and write personal cycling biographies.

### B. Membership Invitation System
- Prospective members navigate to **Profile > "Become a Cycle.exe Member"**.
- Enter single-use, cryptographically secure invitation codes generated by the Super Admin (`CYCLE-XXXX-XXXX`).
- Atomic verification and redemption prevents code reuse and enforces member capacity limits.
- If member privileges are revoked, the user's account immediately reverts to Public status across all active views in real time.

### C. Community Feed & Discussion
- Real-time post feed with photo uploads (image format & size validation up to 5MB, upload progress indicators).
- Real persistent Like/Unlike system with atomic counters.
- Comment threads with anti-bullying reporting system.
- Moderation reports submitted directly to the `/reports` queue for review by moderators.

### D. Mission Operations
- Historical mission records preserved:
  - **Mission 001**: Rajendrapur Loop (37.7 km)
  - **Mission 002**: Nestlé ↔ Nourish Poultry Out-and-Back (32.0 km)
  - **Mission 003**: Bhakowadi Orphanage Bridge Duo Ride (34.0 km)
- Dynamic community missions with route descriptions, start/end dates, targets, rules, difficulty badges, and finisher rewards.
- Created, edited, published, or archived exclusively by the Super Admin.

### E. Distinct Dashboards
- **Regular Admin Dashboard**:
  - Content moderation queue for reported posts and comments.
  - Review flags (bullying, harassment, spam, threats), add notes, dismiss, or hide offending content.
  - Strictly blocked from seeing private login counts, active session totals, invitation codes, or role controls.
- **Super Admin Dashboard**:
  - Live private metrics: total registered users, members, admins, active session heartbeats.
  - User and role management: promote/demote between `PUBLIC`, `MEMBER`, and `ADMIN`; suspend and reactivate accounts.
  - Invitation codes management: generate tokens, view redemption status, set slot limits, revoke tokens.
  - Security audit log stream tracking all privileged actions.

## 3. Technology Stack

- **Frontend**: React 19, TypeScript, Vite, Tailwind CSS, FontAwesome 6.
- **Backend**: Express on Node.js 22 with Vite middleware, REST APIs (`/api/*`).
- **Database**: Cloud Firestore with Attribute-Based Access Control (ABAC) in `firestore.rules`.
- **Storage**: Firebase Cloud Storage for profile avatars and post photos with `storage.rules`.
- **Security**: Cryptographic hashing (`sha256`), rate-limiting, server-side role validation, audit trails.

## 5. GitHub Pages Deployment Guide (Fixing Blank White Page)

If you deployed the repository to GitHub Pages and experienced a blank white page, this is caused by two common Vite/GitHub Pages pitfalls:
1. **Asset Base Path Mismatch**: By default, Vite looks for JavaScript and CSS bundles at the domain root (`/assets/index.js`). Since GitHub Pages serves repositories under a subfolder (`https://ananta-ace.github.io/Cycle.exe/`), the browser returns `404 Not Found` for the bundles, causing a blank screen.
2. **Serving Source Code (`.tsx`) Instead of Compiled `dist`**: If GitHub Pages is configured to serve from the repository root (`/`), browsers cannot execute raw TypeScript (`.tsx`) files, failing immediately.

### How this was resolved:
- **Relative Base Path**: `vite.config.ts` is configured with `base: './'` so that all bundle scripts, stylesheets, and assets load seamlessly regardless of whether the site is hosted at the root domain or inside a subpath like `/Cycle.exe/`.
- **404 SPA Fallback**: The build pipeline automatically generates `dist/404.html` from `dist/index.html` so direct navigation and refreshes never hit a GitHub 404 page.
- **Automated GitHub Actions Deployment**: A `.github/workflows/deploy.yml` workflow is included to build and publish the `./dist` bundle automatically on every push.

### Step-by-Step GitHub Pages Setup:
1. Push your repository to GitHub (`main` branch).
2. Go to your repository on GitHub and click **Settings**.
3. In the left sidebar, click **Pages**.
4. Under **Build and deployment**:
   - Set **Source** to **GitHub Actions**.
5. Push any commit to `main` (or go to the **Actions** tab and click **Run workflow** on *Deploy to GitHub Pages*).
6. Your site will automatically build and go live at `https://<username>.github.io/<repo-name>/` with no blank page!

*(Alternative manual deploy)*:
If using a `gh-pages` branch instead of GitHub Actions:
```bash
npm run deploy
```
Then under **Settings > Pages**, choose **Deploy from a branch** and select the `gh-pages` branch with the `/ (root)` folder.
